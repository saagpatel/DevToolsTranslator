# ADR-008: Hostile Import Security

Status: bounded worker protocol plus hostile-corpus packet-capture, metadata-only HAR, metadata-only OTLP JSONL trace, fixed-member Glassbox Evidence Bundle, and native Apple-log projection parsers implemented; raw Apple source adapters remain gated
Owner: import owner and privacy/security gatekeeper

## Decision

All imports are hostile, including internally consistent or signed bundles. Format parsers run in a separate App-Sandboxed worker with no network entitlement, no canonical database or key access, and no migration/publication authority. The trusted host opens the selected source read-only and passes only a read-only handle. The worker emits bounded framed records or writes a capability-limited staging artifact; a trusted import coordinator validates it and asks storage to atomically publish. Cancellation, timeout, or crash publishes nothing.

Initial ceilings are: 4 GiB compressed input, 16 GiB expanded input, 100:1 compression ratio, 10,000 members, one container nesting level, 16 MiB source record, 10 million events, 1 MiB IPC frame, 768 MiB resident worker memory, 30-minute wall time, and a 30-second no-progress watchdog. Per-format policy may lower but not raise these values without an ADR revision. The host kills the worker on budget breach and records a quarantined loss/failure receipt.

Reject absolute/traversal paths, symlinks, devices, executable bits/content, duplicate or case-colliding names, recursive containers, invalid lengths, unsupported major schemas, and manifest/file disagreement. Imported strings render as text only.

## Rejected

UI-process parsing, `read_to_end` for unbounded members, extraction before validation, silent partial import, or treating a signature as parser safety.

## Oracle

Fuzzing and malicious corpora cover ZIP bombs, traversal, malformed HAR/OTLP/PCAP, large strings, duplicate entries, oversized IPC frames, cancellation, forced crash, timeout, and restart. Peak resources remain within the declared budget and no partial investigation becomes visible.

The first executable slice is `apps/glassbox-import-worker` plus `scripts/glassbox/run_hostile_import_gate.sh`. It proves a no-storage/no-key dependency closure, Developer-ID-signed App Sandbox execution without network entitlements, denied socket creation, per-record and per-frame bounds, fail-closed malformed/unknown/oversized input, cancellation without an end frame, RSS enforcement, deterministic mutation fuzzing with zero parser panics, complete-stream coordinator validation, and process-abort rollback. Each parser must add its format-specific hostile corpus before enablement.

PCAP/PCAPNG is enabled only through the metadata-only streaming path and corpus in `glassbox-network-import`; it never retains raw payload or asserts process attribution. HAR 1.2 is enabled only through the streaming metadata projection in `glassbox-har-import`: it retains bounded timing, method, status, redacted URL shape, and response size while discarding credentials, host, path, headers, cookies, query values, bodies, and server addresses. Unknown HAR extensions fail closed until explicitly covered by a revised corpus and oracle.

OTLP file import is enabled only for UTF-8 JSON Lines containing trace data, following the OpenTelemetry [File Exporter](https://opentelemetry.io/docs/specs/otel/protocol/file-exporter/) and [OTLP JSON encoding](https://opentelemetry.io/docs/specs/otlp/#json-protobuf-encoding) shapes. It retains trace/span identifiers, nanosecond intervals, integer enum state, flags, drop counts, and source-declared parent edges. Resource values, instrumentation details, span names, attributes, events, links, status messages, and baggage are validated under bounded schemas but never emitted. Mixed signals, unknown fields, malformed identifiers, inverted times, duplicate spans, and incomplete streams fail closed. The project requirement for fail-closed imported schemas intentionally remains stricter than the network-receiver rule to ignore unknown OTLP fields. Binary Protobuf, metrics, logs, and profiles remain disabled pending separate bounded decoders, corpora, and oracles.

Glassbox Evidence Bundle import is enabled through the fixed-member `GLSBX001` container, not ZIP or a general archive extractor. The manifest and exactly two NDJSON members are length-, count-, and SHA-256-bound; only format major 1 and current/N-1 minor versions are accepted. There are no filenames, paths, links, executable bits, recursive members, or extraction operations. The worker rejects duplicate semantic IDs and relation hashes, rematerializes every observation with bundle-root-bound materialization and lineage IDs, and emits `End` only after full integrity and trailing-data validation. Corruption, truncation, trailing bytes, unsupported versions, duplicate identities, and interrupted frame delivery publish nothing. Raw Apple containers remain gated behind ADR-014's native adapter corpora and oracles.

The native shell enables only HAR, OTLP JSONL, PCAP/PCAPNG, and `GLSBX001` files. `NSOpenPanel` supplies explicit user selection; the app opens one regular non-link file read-only, hashes and rewinds that same descriptor, and passes the descriptor to the fixed bundle-relative Rust helper. The user path is absent from arguments, environment, diagnostics, receipts, and evidence locators. The helper rehashes the bytes while parsing, buffers only a bounded worker stream, requires `End`, validates the batch in the evidence kernel, and returns at most 200 presentation rows in an 8 MiB payload. The shell replaces its current workspace only after the returned payload passes native validation; cancellation, timeout, parse failure, digest mismatch, and malformed output preserve the existing investigation.

Apple unified-log projection is enabled only for the internal `glassbox-apple-log-projection/v1` stream emitted by the native adapter described in ADR-014. The header and strictly ordered metadata-only entries are bound by a required terminal count and SHA-256. Missing terminal state, digest mismatch, ordinal gaps, unknown fields, string-valued log content, malformed timestamps, truncation, and trailing data fail before the worker emits `End`. This enables hostile testing and atomic publication without pretending that Rust understands Apple's private `.logarchive` container. Direct user-selected `.logarchive` import remains gated until a valid archive corpus proves the signed `OSLogStore` child mode end to end. Instruments `.trace` remains gated until the `xctrace` conversion path meets ADR-014's availability, timeout, staging, sandbox, and corpus requirements.
